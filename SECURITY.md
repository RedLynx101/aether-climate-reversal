# Security policy

## Supported code

Security fixes apply to the current `main` branch. Historical research artifacts are not maintained as executable releases.

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting form for vulnerabilities that could expose data, execute code, compromise a maintainer, or affect the public website. Include the affected file and revision, required preconditions, a minimal reproduction, and the likely impact.

Do not open a public issue containing exploit details, credentials, private data, or a working proof of concept. If private reporting is unavailable, open a short issue asking the maintainers to enable a private security channel without including sensitive details.

Ordinary scientific errors, unsupported assumptions, and reproducibility failures belong in the scientific-review or reproducibility issue templates rather than the security channel.
