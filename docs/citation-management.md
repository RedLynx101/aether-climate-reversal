# AETHER Citation Management

Project title: AETHER: Atmospheric Engineering Through High-Energy Removal

## Source Workflow

1. Add every candidate source to `references/source-register.md`.
2. Put source-specific notes in `research/source-notes/`.
3. Add a BibTeX entry to `references/bibtex/sources.bib` when the source has enough metadata.
4. Save PDFs in `references/pdfs/` only when licensing and access allow it.
5. Save ephemeral web evidence in `references/web-archives/` as screenshots, exported PDFs, or archive notes.

## Reliability Tags

Use these tags in source notes:

- `primary`: original data, official report, peer-reviewed paper, company statement, regulatory filing.
- `secondary`: news article, analysis site, blog, commentary, or summary.
- `social`: X, LinkedIn, YouTube, podcast, or livestream claim.
- `lead`: useful lead, not yet citation-grade.
- `verified`: checked against source text in this repo.
- `needs verification`: not yet checked or source inaccessible.
- `do not cite yet`: useful for exploration but too weak for academic citation.

## Citation Rule

No number goes into the proposal or paper unless it has one of:

- A primary source citation.
- A clearly labeled assumption table entry.
- A model output generated from documented inputs.

## Social Media Claims

Social posts can matter for robotics and AI deployment because companies sometimes disclose production, performance, or timelines there before publishing formal documents. Treat those claims carefully:

- Preserve the URL.
- Record the speaker, date, and exact claim if accessible.
- Capture a screenshot or archive when possible.
- Look for an official company page, transcript, filing, or independent reporting.
- If the post is deleted or inaccessible, cite the secondary record only as evidence of reported claim, not as settled fact.
